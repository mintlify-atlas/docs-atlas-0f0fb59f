HellDots works with every major server-rendering framework, but DOM-dependent widgets and SSR share a fundamental tension: the server has no `document`, no `window`, and no page to mount a toolbar onto. HellDots resolves this cleanly — importing the package on the server is completely safe because nothing touches the DOM at import time. The widget only does DOM work when `createCommentOverlay` is called, and you control exactly when that happens.

## Server-side safety

The package's entry point (`src/index.js`) only exports a factory function. No module-level side effects touch the DOM, so bundlers that evaluate imports on the server — Next.js App Router, Remix's loader pipeline, Astro's build — won't encounter `document is not defined` errors at import time.

```js
// Safe to import anywhere — server, edge, or browser
import { createCommentOverlay } from "helldots";

// Only call createCommentOverlay() in client-side code
```

## Framework examples

<Tabs>
  <Tab title="Next.js App Router">
    Mark the component `"use client"` and initialize inside `useEffect`. The empty dependency array means the overlay is created once after the first render and torn down when the component unmounts.

    ```tsx
    "use client";

    import { useEffect } from "react";
    import { createCommentOverlay } from "helldots";

    interface Props {
      user: { name: string };
    }

    export function CommentsOverlay({ user }: Props) {
      useEffect(() => {
        const overlay = createCommentOverlay({
          user,
          persistence: "localStorage",
        });

        return () => overlay.cleanup();
      }, [user]);

      return null;
    }
    ```

    Add the component to your root layout so it's present on every page:

    ```tsx
    // app/layout.tsx
    import { CommentsOverlay } from "@/components/CommentsOverlay";

    export default function RootLayout({ children }: { children: React.ReactNode }) {
      return (
        <html lang="en">
          <body>
            {children}
            <CommentsOverlay user={{ name: "Ana" }} />
          </body>
        </html>
      );
    }
    ```

## Deferred initialization with `autoInit: false`

For situations where you need the overlay instance before you're ready to mount it — for example, to pre-wire callbacks before the component tree is ready — pass `autoInit: false`. Instead of a `CommentOverlay` instance, `createCommentOverlay` returns an initializer function you call when you're ready:

```ts
import { createCommentOverlay } from "helldots";

// Returns () => CommentOverlay instead of CommentOverlay
const initialize = createCommentOverlay({
  autoInit: false,
  user: { name: "Ana" },
  persistence: "localStorage",
});

// Later, when you're ready to mount the DOM
const overlay = initialize();
```

This is useful when you need to set up the configuration object early (perhaps in a module that runs before React mounts) but want to defer the actual DOM work until later.

## `cleanup()` and React StrictMode

React 18 StrictMode intentionally mounts and unmounts every component twice in development to surface cleanup bugs. HellDots has been hardened against this since 0.5.0: `cleanup()` called while the document is still loading cancels the deferred mount, so the zombie UI that used to appear when StrictMode unmounted during the initial load is gone.

Always return `cleanup()` from your `useEffect`:

```tsx
useEffect(() => {
  const overlay = createCommentOverlay({ user, persistence: "localStorage" });

  // This runs on unmount — required for StrictMode safety and route cleanup
  return () => overlay.cleanup();
}, [user]);
```

`cleanup()` removes the `<helldots-root>` element from the DOM, detaches all event listeners, and disconnects all observers. After calling it the `overlay` instance should be considered dead — create a new one if you need the widget again.
